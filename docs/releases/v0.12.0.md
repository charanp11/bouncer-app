**New: Bouncer works with Cursor CLI too.**

In Settings, **Cursor CLI hooks** → **Install…** shows the exact change to Cursor's own `~/.cursor/hooks.json` (your own Cursor hooks there stay as they are) and saves it on your yes, with a dated backup. The row shows only when there's a `~/.cursor` folder. What Cursor gets is the same as Copilot, on purpose:

- **Watch-only, plus Deny on risky shell commands.** Cursor's sessions show in the island. With **Guard every mode** on, a risky shell command gets a card with **Deny** and **Let Cursor decide** (which sends nothing). Unanswered, the card goes after 100 seconds and Cursor decides.
- **No Allow from Bouncer.** Cursor's hook runs before every shell command, whether or not Cursor would ask, so Bouncer never allows for Cursor and your rules never answer for it: Cursor's own rules and prompt decide.
- **Shell commands only.** File edits, reads and MCP tools aren't shown as requests.
- **Fail-safe:** if Bouncer is closed, missing, crashed or slow, Cursor never refuses a command because of it (tested with each case). Each shell command takes about 0.75 s longer on Windows.

**Tested with the real Cursor CLI 2026.10.22 on Windows**, with a live model on a free account in a test profile (Privacy Mode on).

**Also in this release, a privacy fix.** Cursor's CLI also runs the hooks in `~/.claude/settings.json` (when any of them has a matcher), without their arguments, and sends your email address with every hook. Bouncer now ignores that input: it never reaches the app, nothing is shown, and Cursor carries on as usual. Claude Code, Codex and Copilot CLI hooks are unchanged.

If you're on 0.8.1 or later, Bouncer offers this update itself: "Bouncer 0.12.0 is ready" in the island; click **Update**.
