**New: Bouncer works with GitHub Copilot CLI too.**

In Settings, **Copilot CLI hooks** → **Install…** shows the exact file Bouncer writes (`hooks/bouncer.json` in Copilot's folder, `~/.copilot` or `$COPILOT_HOME`) and saves it on your yes. What Copilot gets is less than Claude Code, on purpose:

- **Watch-only, plus Deny on risky commands.** Copilot's sessions show in the island, and the island says when Copilot is asking in its terminal. With **Guard every mode** on, a risky command gets a card with **Deny** and **Let Copilot decide** (which sends nothing). Unanswered, the card goes after 100 seconds and Copilot decides.
- **No Allow from Bouncer.** Bouncer never allows anything for Copilot and your rules never answer for it: an allow from a hook would override the deny rules you set in Copilot, so Copilot's own rules and prompt decide.
- **No questions or plans** in the island; it shows that Copilot has a question in the terminal.
- **Nothing visible inside Copilot's sandbox** (`--sandbox`): its hooks can't reach Bouncer there, and Copilot carries on as usual.
- **Fail-safe:** if Bouncer is closed, missing or broken, Copilot never refuses a tool because of it.

**Needs Copilot CLI 1.0.67 or newer** (older versions treat a slow hook as a refusal).

**Tested with the real Copilot CLI 1.0.105 (also 1.0.97 and 1.0.67) and a local test model, with no GitHub sign-in; not yet with a live model.**

If you're on 0.8.1 or later, Bouncer offers this update itself: "Bouncer 0.11.0 is ready" in the island; click **Update**.
